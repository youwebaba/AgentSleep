# Attended desktop trial

Keep the operator at the PC for every display change in this procedure. Start with the read-only inventory, a working restore hotkey and the standalone restore command within keyboard reach. Run the first switch as a timed trial. Let the watchdog return the desktop once before testing longer sessions.

## Set up one browser session

1. Record which physical monitor Windows marks as primary in **Settings → System → Display**. Note each monitor’s position, orientation, resolution and refresh rate. A small vertical offset matters. Keep any equipment identifiers and screenshots on the machine.
2. Open [the local fixture](../fixture/index.html) in a normal, visible browser window on the primary screen. Use the same tab, browser profile, desktop agent, screenshot method and input method for all three runs. Record which agent/browser pair you used. Keep private pages out of view.
3. Start a fresh fixture run before each condition. It supplies a different test string and a visible clock. Have the operator record the UTC time of the last panel entering standby and the first panel waking. Use the monitors’ standby indicators or another independent observation. Record “dark, power state unknown” if the hardware offers no way to tell.

## Run the three conditions

| Condition | Prepare the desktop | What the operator observes |
| --- | --- | --- |
| Physical panels on | Exit AgentSleep. Keep all physical panels on. | Confirm that the normal agent can see the current screen and that the page receives its click and text. |
| Normal Windows idle-off | Keep AgentSleep closed and let Windows reach its own display idle timeout. If it is set to **Never**, an operator may choose a finite display timeout for this control and put the original value back afterward. | Note whether the agent wakes a panel, whether input arrives while all panels are dark, and whether any event first appears after wake. |
| AgentSleep virtual-only | With approval at the PC, start an attended trial with the same browser tab already open. Wait for all physical panels to enter standby. | Remain by the panels through both captures, the click and text entry. Note any panel that stays lit, shows a no-signal message, wakes, or requires its power button. |

In every run, have the agent take a desktop screenshot and read the current clock and challenge from the pixels. Have it click the fixture’s counter, focus the input and type that exact challenge. Take a second desktop screenshot after the clock advances. Verify a new clock reading, the advanced counter and a text match. Record the fixture’s click-received and text-match times. Compare those times with the operator’s observation interval. If time expires or a panel wakes first, keep that outcome and start a new run with a new challenge.

A virtual-only pass requires both browser events and a fresh capture while **every** physical panel is still dark. A delayed event timestamp after wake directly answers the reported symptom. Headless runs, DOM automation, script-generated events and a screenshot by itself cannot establish this result. A run requiring a monitor’s power button can establish input compatibility, but leaves automatic standby on signal loss unverified for that monitor.

## Verify recovery

After the automatic rollback, compare the original primary, all three physical targets, positions, modes and orientations against the baseline. Verify that the selected virtual target is available but inactive, and that the same browser window is reachable on a physical screen. Compare its monitor, window bounds and minimized or maximized state with the pre-trial observation. In separate approved trials, exercise the restore hotkey, the standalone restore command and loss of the tray process while leaving the watchdog running. Record whether recovery was exact or whether only a fallback screen was recovered.

The November 23, 2026 baseline used Codex Windows Computer Use with Windows.Graphics.Capture and desktop input in a headed Microsoft Edge window. The counter advanced from zero to one and the fresh screenshot showed the exact challenge match. Times in the table are UTC. Keep screenshots and private run notes outside the repository. One agent/browser/capture combination establishes a result for that combination.

For the first idle-off observation, AgentSleep was closed. An independent guard acknowledged readiness, then the AC display timeout changed from Never to 60 seconds. Windows reported off almost immediately because the desktop was already idle. The clock visible in both captures was the last frame before that notification. The agent reported “failed to activate captured window” with the panels on and again during idle-off. A fresh fixture run could not be started, so this interval supplies no click or text latency measurement. The guard restored the original timeout at 23:19:38.805 UTC. Both AC and DC read back as Never. A separate display-wake request brought the session display status back to on.

For the fresh idle-off run, the operator had installed the signed driver. Windows had added the virtual target while preserving the three physical monitors and primary. AgentSleep was still closed. The pre-click capture showed the clock at the Windows off notification. The post-input capture showed a fresh clock, one click and an exact text match. The operator reported all panels physically dark through typing even though Windows had already reported the session display on. The guard restored Never at 23:25:45.942 UTC and both AC and DC read back as zero.

For the timed AgentSleep trial, the signed target was already active alongside the three physical displays. The watchdog recorded `Isolated` at 23:29:27.608 UTC. The desktop agent initially found Edge minimized, then activated the same window on the 800 × 600 virtual desktop. Both browser events and the fresh screenshot preceded `Restoring` at 23:29:51.715. The watchdog completed rollback at 23:29:52.372. A separate `QueryDisplayConfig` read matched every pre-trial target, including the original primary, positions, refresh rates and rotations. The fixture clock is redrawn periodically, so its displayed value can be a fraction of a second earlier than an event timestamp in the same screenshot.

That first rollback brought back the physical monitors and kept the installer's fourth display active. The operator could not reach Edge. With all three physical paths already verified, an attended recovery disconnected the selected virtual target. Independent reads then matched the original three-screen desktop with the signed target still available to reconnect. A read-only window check found both Edge windows visible on physical screens, including the fixture. The test collected no pre-install window rectangles for that first run.

During a later rehearsal, all three physical outputs stayed active while the virtual display was attached and disconnected. The independent timeout returned the desktop to exactly three outputs. Both observed Edge windows retained their physical monitor, exact rectangle and show state. No virtual-only session began during this rehearsal.

## Follow-up recovery checks

With the installer's four-display starting layout reproduced, a topology trace saw virtual-only at 23:55:14.341 UTC, the original three physical paths alongside the virtual display at 23:55:15.111, and precisely the three original physical paths at 23:55:15.800. The watchdog returned early. Both Edge windows were on physical screens but minimized at the post-restore observation. A separate simulated test reproduced a journal-replacement race that could make the watchdog exit. The fixed watchdog keeps checking the owner and its deadline through a replacement.

In a subsequent trial starting with only the three physical monitors, both Edge windows were visible before entry. Windows minimized both when the physical paths disconnected. AgentSleep's browser verification then requested recovery after about 5.7 seconds. The operator observed the automatic return. This build recorded all tray requests as `Manual`. After the selected virtual path disconnected, both windows matched their original physical monitor, rectangle and show state. This attempt did not establish keyboard recovery.

On November 24 UTC, the updated tray verified virtual-only at 00:08:40.377. Windows minimized both previously visible Edge windows during entry. Both were visible on the virtual screen by 00:08:42.182. The registered hotkey arrived at 00:08:56.374, 16.0 seconds after isolation. The fixture and the three physical display paths initially returned to their original positions with the virtual path inactive. One second later the physical paths began disconnecting and reconnecting as the monitors woke. At 00:09:02.060 all three physical paths matched again and the virtual display was active. A separate recovery guard disconnected it. The fixture matched its original location and size. The other Edge window was minimized on a physical screen. This run verified hotkey delivery and corrected browser entry. The app's early exact-recovery result missed the late reconnect.

In the standalone command trial, AgentSleep waited for the physical paths to settle before disconnecting the virtual target. The same headed Edge fixture, run `75E92C1F45A94200`, showed a live clock of 00:16:22.760 on the 800 × 600 virtual desktop. It received the click at 00:16:25.550 and an exact match for a fresh challenge at 00:16:37.767. The post-input capture showed one click, the match, and the clock at 00:16:37.748. Windows reported zero active physical paths during those actions. The standalone command requested restore at 00:16:43.472; the physical paths disconnected and reappeared during wake. The original three stabilized alongside the signed virtual target at 00:16:49.105. The virtual path disconnected at 00:16:54.793, and AgentSleep recorded completion at 00:17:00.847. The command returned `0` with the tray still running. An independent read matched the three original physical paths and primary. The external safety guard confirmed the result without changing the layout.

The operator confirmed that all three panels stayed dark through the standalone trial's click and text. Standby indicators were uncertain during this run. Both Edge windows were visible before entry and on the virtual screen. An overlapping window covered the first capture, so the agent brought the known fixture forward before issuing input. After stable physical recovery the fixture was visible on a different physical monitor at a different size, and the other Edge window was minimized. Correct physical outputs alone did not establish exact window recovery.
